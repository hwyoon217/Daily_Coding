# 예산

- 플랫폼: 프로그래머스 (Lv.1, 정렬)

## 접근

- 신청 금액이 적은 부서부터 지원해야 지원 가능한 부서 수가 최대가 되므로, `d.sort()`로 오름차순 정렬 후 시작
- `enumerate(d)`로 인덱스(`i`)와 값(`s`)을 같이 꺼내면서, 누적합(`tot`)이 `budget`을 넘는 순간의 `i`가 곧 "그 전까지 지원 가능했던 부서 수"가 됨
- 끝까지 넘기지 않고 다 돌면 전체 부서(`len(d)`) 지원 가능

```python
def solution(d, budget):
    d.sort()
    tot = 0
    for i, s in enumerate(d):
        tot += s
        if tot > budget:
            return i
    return len(d)
```

## 배운 점 / 실수

- 최초 작성 시 `for i, s enumerate(d):`처럼 `in`을 빠뜨려 문법 에러가 남 — `for ... in enumerate(...)` 형태를 항상 확인할 것
- 처음엔 `tot`에 더하기 **전에** `if tot < budget: return i`를 체크하는 구조라, 첫 반복(`i=0`)에서 `tot`이 아직 0인 상태로 조건이 바로 참이 돼버려 무조건 0을 반환하는 로직 오류가 있었음
  - 올바른 순서는 "① 이번 원소를 먼저 누적합에 더한다 → ② 그 결과로 budget 초과 여부를 판단한다"임. 순서를 반대로 하면 판단 기준이 한 칸씩 밀려서 틀림
- 반복문이 끝까지(초과 없이) 다 돈 경우, 루프에 남은 `i` 값을 그대로 반환하면 `len(d) - 1`로 실제 정답보다 1 적게 나옴(0-index라서) → 이런 경우엔 `return len(d)`로 명시적으로 전체 개수를 반환해야 함
- 인덱스 관리를 `enumerate`가 자동으로 해주므로 별도의 `i += 1`은 불필요함
- 변수명으로 `sum` 대신 `tot`을 사용해 내장 함수 `sum()`을 가리는 것을 피함 (지난 "두 개 뽑아서 더하기" 리뷰 때 짚었던 부분)
