# 게임 맵 최단거리

- 플랫폼: 프로그래머스 (Lv.2, BFS)
- 날짜: 2026-10-06 업로드 (실제 풀이는 출장 중, 정확한 날짜 미기록)
- 2026-09-07 기준으로는 "답만 보고 넘어간" 문제였는데, 이번에 처음 푸는 것처럼 스스로 다시 풀어서 통과함.

## 접근

- `(행, 열, 거리)`를 튜플로 큐에 넣는 방식의 BFS. 방문 처리는 `visited`, 거리는 큐 안에서 같이 들고 다님
- 도착 칸(`n-1, m-1`)에 도달하는 순간 바로 거리 반환 (BFS라 가장 먼저 도달하는 경로가 최단)
- 범위 체크(`0<=nr<n and 0<=nc<m`)를 `maps[nr][nc]` 조회보다 먼저 둬서 인덱스 에러 방지

## 배운 점 / 실수 (외울틀.pdf 기준, 연습 중 겪은 것)

- 범위 체크에 방향값(`dr, dc`)을 넣는 실수를 주의해야 함 — 검사 대상은 이동 후 좌표 `nr, nc`. 에러 없이 조용히 틀릴 수 있어서 제일 위험한 패턴.
- 조건을 쉼표로 이어 쓰면(`r==n-1, c==m-1`) 안 되고 `and`로 연결해야 함.
- 방문 처리(`visited[nr][nc] = True`)는 큐에 **넣을 때** 해야 함. 꺼낼 때 하면 같은 칸이 중복으로 큐에 쌓여 효율성 시간 초과 발생.
- `from collections import deque`를 `collection`(s 없이)으로 오타 내지 않도록 주의.

## 남은 복습 과제 → 2026-10-10 완료

- 이번엔 "거리를 큐에 같이 넣는" 방식으로만 풀었음. `dist` 2차원 배열에 거리를 기록하는 방식은 아직 연습 안 함 — 외울틀.pdf 4번 틀 참고해서 같은 문제를 이 방식으로 다시 짜볼 것.

## v1 재작성 + v2(dist 표) 복습 (2026-10-10)

v1(거리를 큐에)을 안 보고 다시 써봄. 실수:
- `q.append((nr, nc, d))`: `d + 1`을 빠뜨림 → 몇 칸을 가도 거리가 1로 고정. **꺼낸 거리 + 한 걸음**을 넣어야 함
- 범위 체크 `9 <= nc` 오타(0 옆 키) → 오른쪽으로 못 가서 항상 -1. 예제 답이 -1로 나오면 범위 체크부터 의심
- 시작점 `visited[0][0] = True` 누락 → 틀리진 않지만 "큐에 넣는 순간 방문 처리"를 시작점에도 적용할 것

v2(dist 표 방식, `solution_v2`) — 코드 안 보고 차이표만 보고 작성:

| | v1 (거리를 큐에) | v2 (dist 표) |
|---|---|---|
| 표 | `visited = [[False]*m ...]` | `dist = [[-1]*m ...]` |
| 시작 | `visited[0][0]=True`, `deque([(0,0,1)])` | `dist[0][0]=1`, `deque([(0,0)])` |
| 방문 체크 | `not visited[nr][nc]` | `dist[nr][nc] == -1` |
| 다음 칸 | `append((nr, nc, d+1))` | `dist[nr][nc] = dist[r][c]+1`, `append((nr, nc))` |
| 끝 | 도착점 꺼내면 `return d`, 못 가면 `return -1` | 끝까지 돌리고 `return dist[n-1][m-1]` |

- 실수: 마지막에 v1 습관대로 `return -1`을 써서 항상 -1 → `return dist[n-1][m-1]`. 못 가면 그 칸이 -1 그대로라 따로 처리할 필요 없음
- `dist` 하나가 visited와 거리를 둘 다 맡음. -1이면 안 간 칸, 숫자가 있으면 이미 간 칸이라 다시 조건을 통과하지 못함
- 시작 칸을 0으로 세는 문제(이동 횟수 등)는 `dist[시작] = 0`
- 막히면 `for row in dist: print(row)`로 BFS가 퍼진 모양 확인
