# 피로도

- 플랫폼: 프로그래머스 (Lv.2, 순열 백트래킹)
- 날짜: 2026-10-06 업로드 (실제 풀이는 출장 중, 정확한 날짜 미기록)

## 접근

- 던전을 어떤 순서로든 고를 수 있고(순서 자체가 결과에 영향) 최대 개수를 찾는 문제라, 타겟 넘버와 달리 `visited` 배열로 "아직 안 간 던전"을 관리하는 백트래킹 사용
- `dfs` 함수 맨 위에서 매번 `answer = max(answer, count)`로 갱신 — 꼭 끝까지 가야만 기록되는 게 아니라 매 단계가 후보가 됨
- 방문 처리(`visited[idx] = 1`) → 재귀 호출 → 되돌리기(`visited[idx] = 0`)의 표준 백트래킹 흐름

## 배운 점 / 실수 (외울틀.pdf 기준)

- **실수 1**: 처음엔 `answer += 1`처럼 더해서 세려 했는데, 이러면 "탐색한 경로의 수"를 세는 게 돼버림. 최대 깊이는 `count`가 들고 있으니 `max()`로 갱신해야 함.
- **실수 2**: `nonlocal answer`를 빠뜨리면 `UnboundLocalError` 발생. `visited[idx] = 1`처럼 리스트 칸만 바꾸는 건 `nonlocal` 없이도 되지만, `answer`처럼 바깥 변수에 직접 대입하는 건 `nonlocal` 필수.
- DFS 경우의 수 틀(타겟 넘버)과의 차이: 타겟 넘버는 idx 순서대로 전부 순회해서 visited가 필요 없지만, 이 문제는 "고르는" 문제라 visited로 중복 선택을 막아야 함.
